# Перехват отрисовки клиента игры (прототип отрисовки в браузере, factorio.darkkeks.me/render/)

`v2-capture.js` — скрипт Frida, который грузится в клиент Factorio через Frida Gadget
(`LD_PRELOAD=~/factorio-camera/hook/gadget.so`, рядом `gadget.config` с путём к этому файлу).

Что читаем: готовые записи кадра `SpriteDrawOrder` в `DrawEngine::load(DrawQueue*)` — игра передаёт сюда каждую
очередь кадра, пока та ещё полная (к `drawEntities` массивы уже разобраны). В записи — итоговая точка на экране,
масштаб, поворот, цвет, вырезка из атласа (так работают «нарезанные» спрайты: подземные конвейеры, сплиттеры) и ключ
сортировки, в котором зашита мировая позиция (x — биты 6–37 минус 2^28, y — биты 35 и выше, единица — 1/256 клетки).
Сервис (`src/map-render.mjs`) переводит экран в мир (масштаб — у камеры, сдвиг — медиана по записям без сдвига спрайта)
и сортирует как игра: по слою, внутри — по ключу; тени (отдельный массив) — одним буфером между слоями 119 и 120,
слой 255 — освещение (днём не видно).
Флаги записи (+0x1c): 0x400 — игра запись пропускает; 0x100 / 0x200 — отразить по горизонтали / вертикали (так рисуются
провода — дугой из общей картинки, — и углы составных спрайтов); 0x10000 — тень. Слой 92 — декали (трава, камни на земле):
на странице поверх подложки-снимка не рисуются, на снимке они уже есть. Провода игра рисует обычными записями
(`WireRendering::draw` создаёт `SpriteDrawOrder` сама, мимо `DrawQueue::draw*`). Ночь — таблица цветов игры
`data/core/graphics/color_luts/lut-night.png` (сервис отдаёт её как `/render/lut-night.png`), подмешанная по темноте;
где светит, остаётся дневной цвет. Подписи на карте (`drawTextReal`, `drawPlainTextOnMap`) в обычном кадре не вызываются;
`drawPlainText` — только интерфейс.

Порядок отрисовки кадра в игре (2.1.24): renderShadowsToWorkingSprite, drawEntities 3..29, 29..120, drawShadowBuffer,
drawEntities 120..125, 125..133, 133..141, 141..153, drawIconLayers 155.., drawEntities 155..159, 160..161,
drawIconLayers 162.., drawEntities 162..255, drawOthers. Устройство структур — в комментариях скрипта.
Пиксели атласов: `copyDataRaw` у `CustomVideoBitmap` (в памяти: BC3 с цветом в YCoCg + BC4 прозрачность) и
`VideoBitmapOpenGL` (RGBA или BC4 для теней), распаковка — `src/bcn.mjs` в отдельном потоке.

`run-test.sh` — тестовый клиент: одиночная игра из копии автосейва на отдельном Xvfb `:93`,
свои папки данных (`~/factorio-camera/hook/data`); сервер и живую камеру не трогает.

Правка скрипта на живой камере применяется только перезапуском клиента-камеры (`kill -TERM -- -$(cat ~/factorio-camera/camera.pid)`,
сервис сам запустит новый): горячая перезагрузка (`"on_change": "reload"` в `gadget.config`) снимала перехваты, пока потоки игры
были внутри перехваченных функций, и клиент падал (SIGSEGV в DrawQueue::draw). Поэтому в `gadget.config` — `"on_change": "ignore"`.
`bpftrace` на клиент с Frida тоже не вешать: обе вещи правят начало одних и тех же функций, клиент падает.
