# discord-voice

Голосовой бот для игры в Factorio. Сидит в голосовом канале Discord, каждого человека слушает отдельно
и передаёт его реплики его собственной сессии Claude (Opus 5.5), которая управляет его персонажем на сервере.
Голосом бот не отвечает; в чат голосового канала пишет реплики людей и текст, который выдаёт Claude.
Обращения ботов к игре видны в `api.log`.

## Запуск

Три процесса в tmux (сессия `0`), у каждого свой лог:

    tmux new-window -d -t 0: -n factorio-api      ~/claude/discord-voice/run-api.sh       # сервер ботов, api.log
    tmux new-window -d -t 0: -n factorio-sessions ~/claude/discord-voice/run-sessions.sh  # сессии Claude, sessions.log
    tmux new-window -d -t 0: -n discord-voice     ~/claude/discord-voice/run.sh           # Discord и звук, bot.log

Они разделены, чтобы обновления не прерывали работу ботов:

| Что изменилось | Что перезапустить | Сессии, саб-агенты и действия ботов |
|---|---|---|
| сервер ботов (`v2/server/`) | `factorio-api` | не прерываются: очереди действий живут в игре, журнал событий дочитывается после запуска |
| мод в игре (`v2/mod/`) | сервер игры: `v2/tools/update-game.sh` | сессии не прерываются; очереди действий продолжаются с того же места; людей выбивает из игры — согласовать |
| правила ботов (`rules/RULES.md`) | ничего — изменения рассылаются сессиям автоматически | не прерываются |
| Discord, звук (`src/main.mjs`, `src/speech.mjs`) | `discord-voice` | не прерываются |
| сессии (`src/sessions.mjs`, `src/agent.mjs`), Claude Code в контейнере | `factorio-sessions` | прерываются: сессии возобновляются с тем же контекстом, саб-агенты теряются |

Голосовой бот заходит в канал, когда там появляется человек, и выходит, когда канал пустеет.
Под одним токеном Discord в голосовом канале может сидеть только один процесс.

## Как это работает

- Человек зашёл в канал → на сервере появляется персонаж «Имя-бот» и запускается сессия Claude этого человека.
  Вышел → бот перестаёт его слушать, но сессия и её саб-агенты продолжают начатое; вернулся — та же сессия.
  Сессии останавливаются только вместе с ботом; контекст сохраняется и между перезапусками (`state-factorio.json`).
- В сессию попадает всё, что человек сказал. Выполнять или промолчать, решает сама сессия: по промпту она
  действует только на явное обращение («Клод», «бот») или на несомненное продолжение своей команды.
- Главная сессия — диспетчер: быстрые справки делает сама, а работу руками поручает фоновому саб-агенту и остаётся
  на связи; новая команда — сообщение саб-агенту или его остановка и новый запуск.
- Игрой боты управляют HTTP-запросами к серверу ботов (см. «Управление ботами»). Персонаж — обычная сущность
  `character` без игрока; правило — действовать как обычный игрок, без читерства.
- У каждого бота своё окружение в контейнере `robot`: оболочка и файлы (Bash, Read, Write, Edit), папка `~/bots/<имя>`
  (на хосте `~/robot/bots/`). Адрес сервера ботов и токен персонажа — в переменных `FX_URL` и `FX_TOKEN`.
  Боты могут писать и запускать любую свою автоматизацию. Отдельного пользователя у них нет: технически им доступно
  всё содержимое контейнера, включая файлы сервера игры и пароль RCON; не трогать это — правило из промпта, а не запрет.
- `say` пишет в игровой чат, и сообщение получают сессии остальных ботов.
- Реплика человека во время работы ничего не прерывает: она встаёт в очередь Claude и читается между действиями.

## Управление ботами (v2/)

Три слоя: бот и его скрипты ходят по HTTP в сервер ботов на хосте, сервер короткими запросами по RCON обращается
к моду, мод исполняет действия по тикам игры и ведёт журнал событий. ТЗ — https://claude.ai/artifact/Lja2bs4TqkDAwHcdNC6EMz.

- **Мод** (`v2/mod/`) — сценарий внутри сохранения: `control.lua` (штатная свободная игра плюс исполнитель) и каталог
  `agent/`. Клиентам ничего ставить не нужно: код приходит вместе с картой. Владеет персонажами, их очередями действий,
  журналом событий, планами и чертежами; всё состояние — в `storage.agent` сохранения. Точка входа — консольная
  команда `/agent <JSON>`, принимается только с консоли сервера. Состояние создаётся и обновляется лениво, при первом
  тике или запросе: при замене сценария игра не вызывает ни `on_init`, ни `on_configuration_changed`. Обработчики
  событий регистрируются только при загрузке (иначе клиенты не смогут войти в игру).
- **Сервер ботов** (`v2/server/`, окно `factorio-api`) — HTTP с JSON: `POST /v2/<операция>` с заголовком
  `Authorization: Bearer <токен>`, описание всех операций — `GET /v2/help`. Токены — `mcp-tokens.json`
  (`{"токен": "имя персонажа"}` или `{"токен": {"admin": true}}`), файл перечитывается при изменении. У каждого
  персонажа своё соединение RCON; журнал событий опрашивается раз в 100 мс. Игрового состояния сервер не хранит.
  Настройки — `v2/server/config.json` (образец — `config.example.json`). Журналы: `api.log` (строка на вызов),
  `v2/server/log/calls-<день>.log` и `full-<день>.jsonl` (полные запросы и ответы), `feedback.jsonl` (замечания ботов).
  Счётчики и время ответа — операция `metrics` (токен администратора).
- **Обновление мода** — `v2/tools/update-game.sh`: останавливает сервер игры, делает резервную копию сохранения
  в `backups/`, заменяет файлы сценария, запускает и проверяет версию. `--remove` возвращает штатный сценарий.
- **Пауза** (`~/robot/bin/pause-guard.py`, исходник — `v2/tools/pause-guard.py`): игра идёт, пока в ней есть люди,
  люди есть в голосовом канале или у любого бота непустая очередь действий; правило исполняет мод одной командой.
  Поставленное действие само снимает паузу, чтение мира — нет.
- **Слежение для людей** — кнопка «Боты» в интерфейсе игры: список ботов, «Следить» (карта едет за ботом),
  «Окно» (окно-камера), метки на карте, по галочке — действие над головой бота и линия до цели ходьбы.
- **Туман войны**: вживую бот видит то, что видит команда (радары, люди) и квадрат 5×5 чанков вокруг ботов (мод сам
  открывает там карту — персонаж без игрока этого не делает); на открытой, но невидимой карте — только вид и место
  построек по памяти карты, без содержимого и врагов.
- **Проверки** (`v2/tests/`, на отдельном экземпляре сервера с копией сохранения, `v2/tools/test-server.sh`,
  `reload.sh`, `test-api.sh`, `test-client.sh`): `core`, `actions`, `planning`, `observe` — действия, досягаемость,
  ходьба, события, повтор запросов, туман; `walk-bench.mjs` — замер ходьбы по критерию ТЗ; `perf.mjs` — скорость,
  независимость ботов, нагрузка на игру.

Для веб-карты и хозяина сессий мод поддерживает в сохранении `storage.vb` (имя бота → сущность персонажа)
и `storage.vb_chat` (реплики ботов).

## Файлы

- `src/main.mjs` — Discord (discord.js + @discordjs/voice, DAVE), приём звука, лог в чат.
- `src/speech.mjs` — Silero VAD и распознавание GigaAM v3 через sherpa-onnx-node 1.x; модели в `models/`.
- `src/sessions.mjs` — хозяин сессий: держит процессы Claude, раздаёт им реплики, игровой чат и обновления правил.
- `src/agent.mjs` — одна сессия Claude; в системном промпте только неизменное ядро.
- `src/game-api.mjs` — токены персонажей и вызов сервера ботов из кода на хосте.
- `rules/RULES.md` — правила поведения ботов; копия лежит в контейнере (`~/robot/bots/RULES.md`), боты читают её сами.
- `src/rcon.mjs` — клиент RCON для веб-карты и хозяина сессий (`rcon.json` — адрес и пароль).
- `v2/` — управление ботами: мод, сервер, инструменты и проверки.

## Контейнер robot (robot/)

Процессы Claude и сервер Factorio живут в контейнере `robot` (`robot/compose.yml`): без root и capabilities,
8 ГБ / 4 ядра, домашняя папка — `~/robot` на хосте, автозапуск после перезагрузки хоста. Модель зафиксирована
политикой `robot/managed-settings.json` (только Opus 5.5). Главный процесс — supervisord, сервисы в `~/robot/services/`:

- `factorio-space-age-1` — сервер: игра на UDP 34197, RCON на 127.0.0.1:27015 хоста, `auto_pause: false`.
- `pause-guard` — ставит игру на паузу, когда на сервере нет игроков и в голосовом канале нет людей
  (бот раз в 15 секунд обновляет `~/robot/voice-active`). Если бот выключен и никого нет в игре — пауза.

    cd robot && docker compose up -d --build     # пересобрать и перезапустить контейнер
    docker exec robot supervisorctl status       # состояние сервисов
    docker exec -it robot claude                 # один раз: войти в подписку (/login)

## Доступ для внешних ботов

Тот же сервер ботов доступен снаружи: `http://h1.darkkeks.me/factorio-mcp/v2/<операция>` (nginx в контейнере
`karoo-apk` → `172.25.0.1:8765` на хосте; путь исторический), описание — `GET …/v2/help`. HTTPS на хосте нет, токен идёт
открытым текстом. Через nginx ожидание действия ограничено 50 секундами: дальше ответ `running` и `wait_action`.

## Веб-карта (https://factorio.darkkeks.me)

`src/map.mjs` — публичная страница без авторизации: карта базы настоящей графикой игры, метки ботов и игроков,
панель бота по нажатию (чем занят, инвентарь, очередь крафта, здоровье, кнопка «следить»), сводка (исследование,
электросеть, тревоги, лента сообщений ботов) и «живое окно» — видео из клиента-камеры. Только читает игру. ТЗ и результаты проверок — `docs/web-map-tz.md`.

    tmux new-window -d -t 0: -n factorio-map ~/claude/discord-voice/run-map.sh     # запуск, лог в map.log
    tmux kill-window -t 0:factorio-map                                             # остановить вместе с клиентом-камерой

- Картинку даёт **клиент-камера**: полная копия игры в `~/factorio-camera/factorio` (той же версии, что сервер;
  обновлять вместе с ним), запущенная под Xvfb на программном рендере и подключённая к серверу игроком `camera`
  в режиме зрителя. Сервис сам её запускает, следит через RCON и перезапускает (обрыв связи, перезапуск сервера,
  зависание); лог клиента — `~/factorio-camera/camera.log`. Клиент привязан к потокам процессора 2–7 (`CAMERA_CPUS`),
  окно 1280×720 на дисплее Xvfb `:96`; занимает около 2 ГБ памяти и 4–5 потоков постоянно. Запуск — около минуты.
- Сервис через RCON командует `game.take_screenshot` для игрока `camera`: клиент пишет готовые тайлы 512×512 (JPEG)
  в свой `script-output`, сервис раскладывает их в `~/factorio-camera/tiles/<уровень>/<x>_<y>.jpg`. Уровней шесть:
  от 32 пикселей на клетку до 1 (мельче игра не снимает). Около 14 тайлов в секунду.
- Очерёдность: то, на что смотрят зрители, — раз в 2 секунды (сколько успеет камера); 32×32 клетки вокруг каждого
  бота и игрока — раз в 5 секунд; всё остальное
  разведанное — фоном раз в 10 минут. На паузе каждый тайл снимается один раз. Возраст картинки показан в углу страницы.
- **Живое окно** (кнопка на странице или ссылка с `?live`): ffmpeg снимает дисплей клиента и отдаёт H.264 1280×720,
  30 кадров/с, около 2 Мбит/с по WebSocket `/video`; задержка около секунды. Кодирование идёт, только пока окно
  кто-то смотрит. Вид один на всех: камера держит в центре (`centered_on`) того, кого выбрали кнопкой «следить»
  (последний выбор главнее), а в режиме «авто» — того, кто сейчас движется. Интерфейс клиента скрыт настройками
  игрока `camera`. В видео настоящее время суток, тайлы карты всегда дневные. Нужен браузер с H.264.
- Игрока `camera` не считают человеком: `pause-guard` (`~/robot/bin/pause-guard.py`) и `status` ботов его пропускают.
- Сервер должен пускать клиента без учётной записи factorio.com: `"require_user_verification": false`
  в `server-settings.json` (сервер закрыт паролем игры; пароль сервис берёт из того же файла).
- Снаружи: контейнер `factorio-map` (`map-deploy/`, `docker compose up -d`) с `VIRTUAL_HOST=factorio.darkkeks.me` →
  `172.25.0.1:8766`; HTTPS даёт Cloudflare. Старый адрес `http://h1.darkkeks.me/factorio-map/` тоже работает
  (`location` в `~/claude/karoo-zone2-nag/deploy/nginx.conf`).

## Заявки на улучшение (feedback)

Обработчик заявок написан под прежнюю систему инструментов (`src/factorio.mjs`, её больше нет) и к новой не приспособлен:
после перехода на `v2/` его окно остановлено. Замечания ботов теперь пишутся операцией `feedback` в
`v2/server/log/feedback.jsonl`. Ниже — описание прежнего устройства.

У ботов есть инструмент `feedback`: заявка дописывается в `feedback/queue.jsonl`. Что с ней стало, бот видит
через `feedback_status`: свои заявки (или все, `all=true`) со статусом и ответом разработчика. Фоновый обработчик
(`src/feedback-worker.mjs`, окно tmux `feedback-worker`, лог `feedback/worker.log`) раз в 30 секунд смотрит очередь и,
если в ней есть новые заявки, запускает заход — отдельную сессию Claude Code (Fable 5.2, на хосте) с правилами
из `feedback/WORKER_PROMPT.md`: действия MCP должны быть как у обычного игрока, без читерства; любое сомнение — отказ
или обсуждение. Сессия видит всю очередь, сама выбирает заявку или пачку связанных и даёт вердикт по каждой разобранной.
Ей разрешено только читать проект, править `src/factorio.mjs` и `README.md` и запускать `node --check`
и `src/tool-test.mjs`. После захода обработчик проверяет результат, коммитит и перезапускает процесс инструментов (`factorio-mcp`; сессии ботов при этом не перезапускаются);
при любой неполадке откатывает правки (они сохраняются в `feedback/rejected-*.diff`). Всё закоммиченное — и обработчиком,
и руками — он же раз в 30 секунд отправляет на GitHub.

Статусы: `new` → `done` | `rejected` | `discussion`. Очередь разбирается руками так:

    node src/feedback.mjs list [статус]             # список с вердиктами («!» — приоритет)
    node src/feedback.mjs show <id>                 # заявка целиком
    node src/feedback.mjs prio <id>                 # разобрать в первую очередь
    node src/feedback.mjs set <id> <статус> [текст] # сменить статус (new — отправить на повторную обработку)

    tmux new-window -d -t 0: -n feedback-worker 'cd ~/claude/discord-voice && node src/feedback-worker.mjs 2>&1 | tee -a feedback/worker.log'
